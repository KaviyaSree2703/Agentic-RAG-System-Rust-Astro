# Modernization Gap Matrix: v11 Target Specification vs Existing Implementation

This matrix tracks every architectural domain, requirement, existing implementation status, identified gap, planned engineering change, and verification test in accordance with **Agentic RAG System: Complete Design Document v11**.

| v11 requirement | Existing implementation | Gap | Planned change | Test |
|---|---|---|---|---|
| **Release Architecture**: Modular Rust monolith with two distinct binaries (`api` and `worker`) | Single monolithic binary `backend` running Axum HTTP server and performing in-process parsing/indexing | Ingestion runs synchronously in the HTTP request thread; no separate worker process | Restructure `backend` into two binaries: `backend/src/bin/api.rs` (HTTP & SSE) and `backend/src/bin/worker.rs` (background ingestion job queue processor) | Build and run both binaries independently; verify job enqueueing & claiming |
| **Data Architecture**: PostgreSQL with pgvector, full-text search, and Row-Level Security (RLS) | Local SQLite (`rag.db`) with custom migrations table + Tantivy 0.27 BM25 index | No pgvector vector search; no multi-tenant RLS; SQLite/Tantivy lacks transaction-local `TenantTx` isolation | Implement PostgreSQL schema migrations (tenants, documents, chunks, acl_entries, conversations, messages, run_events, idempotency_keys) with `TenantTx` context. Retain backward-compatible Tantivy/SQLite storage adapter for no-Docker local dev fallback. | Schema migration test; RLS isolation unit & contract tests; TenantTx missing context fail-closed tests |
| **Caches & Disposable State**: Redis used ONLY for disposable caches, rate limiting, and 5-min membership cache. Correctness leases in DB. | In-memory Tokio synchronization | No external rate limiter or membership cache | Implement Redis client abstraction for rate-limiting and OIDC group cache with graceful local in-memory degradation fallback when Redis is absent. Ensure conversation leases stay in DB. | Cache failure degradation test; rate limiting test; lease contention test |
| **Object Storage**: S3-compatible tenant-scoped object storage for original docs, normalized text, and citation artifacts | Local filesystem temporary directory (`rag_uploads`) | No tenant prefixing, no object storage abstraction, no persistent storage of original files | Implement `ObjectStore` trait (supporting local filesystem tenant root and S3-compatible endpoints) with tenant-scoped keys (`tenants/{tenant_id}/docs/{doc_id}/original`) | Unit tests for object key isolation and tenant path validation |
| **Identity & Authentication**: OIDC JWT verification (issuer, audience, signature, expiry) + 5-min max membership age | Hardcoded `"default"` user and `"default"` scope across all endpoints | No JWT validation, no OIDC claims parsing, no membership refresh, user input trusted | Implement OIDC authenticator middleware verifying RS256/ES256 JWTs, extracting `sub`, `tenant_id`, and roles, enforcing 5-min cached membership checks | JWT verification tests (valid, expired, tampered, wrong issuer, cross-tenant) |
| **Supported Ingestion Formats**: English-only PDF, DOCX, PPTX. Explicit rejection of scanned PDFs, legacy DOC/PPT, spreadsheets, audio, video | Supports PDF (lopdf), TXT, MD, CSV, JSON, LOG | DOCX and PPTX parsers missing; no optical/scanned PDF detection; legacy/unsupported files not rejected with structured error codes | Implement DOCX & PPTX text extractors using zip/xml parsing; add scanned-PDF text-length check (>50 characters extractable text per page); reject legacy/media formats with `unsupported_format` | Parser unit tests with valid text PDF, scanned PDF, DOCX, and rejected binary formats |
| **Embedding Generation**: `nomic-embed-text-v1.5` at 768 dimensions with task prefixes `search_document: ` and `search_query: ` | Keyword search only via Tantivy BM25 (`content` field) | No vector embeddings generated during chunking; no task prefix enforcement | Implement typed `EmbeddingProvider` generating 768-dim vectors with mandatory `search_document: ` / `search_query: ` prefix; store in chunk records | Embedding dimension & prefix assertion tests; cosine similarity benchmark |
| **Deterministic Pre-Router**: Fixed templates for greetings/thanks; strict referrals (`refer_to_owner`) for general knowledge, live data, exact queries, opinions | Single loop treats all queries as retrieval queries | System attempts to retrieve internal documents for "hello", "what is the capital of France?", or live stock prices | Implement deterministic pre-router classifying queries into `social_reply`, `refer_to_owner`, `ask_user`, or `document_query` before any tool/retrieval call | Test router with greetings, out-of-domain questions, live data requests, and document questions |
| **Structured Plan & PlanValidator**: Structured query plan with subquestions `q1..qN`, acyclic DAG validation, entity/date constraints | Single query string passed directly to search engine | No multi-step query decomposition; no DAG dependency check; no capability check | Implement `PlanValidator` validating subquestions, maximum subquestion count (<=5), dependency acyclicity, and required constraint preservation | Test PlanValidator with valid DAG, cyclic dependencies, >5 subquestions, and missing entities |
| **Registered Tool Registry**: Document search and document lookup ONLY. Web, SQL, CRM, MCP forbidden | Ad-hoc internal call to `search_engine.search()` | Tool definitions are informal and untyped; no compile-time exclusion of forbidden tools | Implement typed `ToolRegistry` registering exclusively `hybrid_document_search` and `document_lookup`; compile-time assertion preventing forbidden tools | Registry membership test; forbidden tool rejection test |
| **Evidence Evaluator**: Evaluator receives subquestions & evidence, judges coverage, returns structured verdict. Does NOT execute tools. | In-memory `EvidenceEvaluator` checking term overlap and average BM25 score | Evaluator mixes term coverage heuristics with confidence threshold; does not track subquestions or quote verifications | Upgrade `EvidenceEvaluator` to validate each subquestion against evidence passages with verbatim substring quotes, authority rules, and structured next actions (`sufficient`, `missing_aspects`, `suggested_query_rewrite`) | Unit tests for complete evidence, missing subquestions, conflicting sources, and zero results |
| **Adaptive Control Loop**: Bounded state machine (START -> ROUTE -> PLAN -> SELECT_TOOLS -> RESERVE_BUDGET -> EXECUTE_TOOLS -> TOOL_HEALTH_GATE -> NORMALISE -> ACL_RECHECK -> EVALUATE -> BUILD_CONTEXT -> GENERATE -> VERIFY_GATE -> PERSIST) | Simple `while attempt < max_attempts` loop in `AgentOrchestrator` | Missing intermediate health gates, budget reservation, ACL recheck, and formal state machine transitions | Refactor `AgentOrchestrator` to execute the explicit v11 state machine with hard caps (max 5 attempts, max 8 tool calls, 40s wall-clock timeout) and atomic budget reservation | State machine trace test; attempt cap test; timeout enforcement test; no-repeat query/tool tuple test |
| **Context Builder**: Delimits untrusted doc text, preserves 1-based source indices & immutable anchors, respects token budget | Basic string concatenation `--- Citation [{}] ... ---` | No untrusted text sanitization/delimiters; no token budgeting; no coverage metadata | Implement `ContextBuilder` structuring XML/delimited context blocks with immutable chunk anchors, source numbers, and gap warnings | Context builder formatting and delimiter isolation tests |
| **Generation Format**: Canonical JSON Lines claim units: `{"u": N, "role": "...", "text": "...", "cites": [...], "reqs": [...]}` | Free-form streaming Markdown text with inline `[1]` brackets | Model emits unverified arbitrary text; parser cannot verify claims before display | Implement JSON Lines claim stream parser and strict generator formatting | Claim unit deserializer tests; out-of-order unit rejection test |
| **Grounding Verification Gate**: Checks P0, P1, C1–C5 (schema, hygiene, approved citation IDs, evaluator relevance, entity/date match, NLI entailment, non-empty cites) | Assumes all citations returned by search are verified (`verified: true`) | No claim-level entailment check; no verbatim quote check; unverified tokens can be streamed | Implement `VerificationGate` executing P0–C5 before emitting answer units. Enforce answer-first rule (unit 1 must pass before tokens stream). | Verification gate test suite (valid claims, fake citation ID, ungrounded entity, conflicting number) |
| **SSE Streaming & Reconnect**: Event types `status`, `token`, `citations`, `verification`, `clarification`, `done`, `error` with monotonic IDs and `Last-Event-ID` replay | SSE events `stage_change`, `tool_event`, `evidence_evaluation`, `context_ready`, `token`, `done`, `error` | Event names differ from v11 spec; no event IDs; no persistence in `run_events`; no reconnect replay | Implement v11 SSE event schema with increasing IDs, buffer into `run_events` (24h retention), support `Last-Event-ID` replay with 10s grace period | SSE parser contract test; event replay test; reconnection limit test |
| **API Versioning & Uniform Envelope**: `/v1/chat/stream`, `/v1/search`, `/v1/documents`, `/v1/health` with uniform error envelope | Legacy `/api/*` endpoints | Endpoints lack `/v1` prefix and standardized v11 error envelope | Implement `/v1` routes; maintain `/api/*` as compatibility wrappers calling shared domain services | API route integration tests for both `/v1` and legacy paths |
| **Astro Frontend Alignment**: UI consumes v11 SSE events, renders claim units & citations, handles referrals & partial coverage | Frontend expects legacy event types (`stage_change`, `tool_event`, etc.) | Frontend SSE parser fails or ignores v11 events; no claim-level citation badge mapping | Update `frontend/src/lib/rag/streaming.ts` and `frontend/src/lib/rag/api.ts` to support v11 events, display structured citations, and handle `refer_to_owner` | Frontend build (`npm run build`); browser interaction verification |
| **Observability & Safety**: Structured tracing, no secret/prompt leaks in logs, realistic health checks | Basic `tracing::info` and hardcoded `uptimeSeconds: 120` | Health check returns fake uptime and mock models; logs lack structured run IDs | Implement structured tracing with `run_id` and `request_id`; compute real database/index health in `/v1/health`; sanitize logs | Health check probe test; log secret sanitization test |
